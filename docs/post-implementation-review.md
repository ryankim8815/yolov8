# 구현 후 오류 검토 및 회귀 테스트

검토일: **2026-11-06 (KST)**. 대상: 사용자 물체 수집·검토·학습·Core ML·모델 전환 기능과 기존 실시간 API.

후속 검증에서 실제 카메라·브라우저·수집·학습·모델 적용을 직접 실행하고 모델 전환의 DB 기록 오류를 추가 수정했다. 최신 결과는 [직접 실행 검증 보고서](direct-execution-review.md)이며, Python 테스트는 환경별 69개로 늘었다. 아래는 1차 검토 기록이다.

기존 자동 테스트 55개는 통과했으나, 오류 경로와 동시 요청을 추가로 검사하면서 아래 문제를 재현했다. 코드를 수정하고 Python 회귀 테스트 13개와 JavaScript 비동기 UI 테스트 5개를 추가했다. 현재 검사 범위에서 실패하는 테스트는 없다. 실제 물체 인식 정확도나 모든 장비 오류가 검증되었다는 의미는 아니다.

## 최종 자동 검사

| 검사 | 결과 |
| --- | --- |
| `.conda/mps` 전체 pytest | **68 passed**, 11.25초 |
| `.conda/coreml` 전체 pytest | **68 passed**, 11.71초 |
| `.conda/train` 전체 pytest | **68 passed**, 11.56초 |
| JavaScript 시작·중지·실패 경합 | **5 passed** |
| 세 환경 `pip check` | 모두 의존성 충돌 없음 |
| Python `compileall`, JS 두 파일 구문 검사 | 통과 |
| `git diff --check` | 통과 |

같은 Python 테스트 68개를 세 환경에서 각각 실행한 결과다. 세 배의 서로 다른 시나리오를 의미하지 않는다. pytest는 하드웨어 대체 입력을 사용한다. JS 검사는 실제 `training.js`를 Node VM에서 실행하고 DOM·HTTP·타이머를 대체하여 요청 순서를 제어한다. 실제 브라우저의 화면 배치 검사를 대신하지 않는다.

각 Python 실행에서 Starlette TestClient의 httpx 지원 중단 예정 경고 1건이 있다. 실패는 아니며 이번 변경에서 의존성 버전은 바꾸지 않았다. `pip check` 실행에는 샌드박스의 사용자 캐시 쓰기 제한 경고가 있었지만 의존성 검사는 완료되었다.

```bash
bash scripts/python.sh mps -m pytest -q
bash scripts/python.sh coreml -m pytest -q
bash scripts/python.sh train -m pytest -q

# Node가 설치되어 있을 때 실행. 서버 실행·프런트엔드 빌드에는 Node가 필요하지 않음
node --test tests/training_ui.test.cjs
node --check app/static/app.js
node --check app/static/training.js

bash scripts/python.sh mps -m pip check
bash scripts/python.sh coreml -m pip check
bash scripts/python.sh train -m pip check
```

이 장비의 JS 검사는 Codex에 포함된 Node 실행 파일로 수행했다.

기존 서비스 서버가 실행 중이지 않음을 확인한 뒤, 카메라를 열지 않는 격리된 smoke 작업을 실행했다. 공개 이미지 10장에 기능 검사용 단일 클래스를 붙여 train 8장/validation 2장으로 나누었다. 실제 사용자 사진과 서비스 DB는 사용하지 않았다.

- 작업: `job-07b7c9fd93384d2792aacfb7efab2de7`.
- 상태: **completed**, 오류·경고 없음.
- 실행: MPS 640, batch 4, 1 epoch → PT 평가 → FP16 Core ML 변환 → 동일 자료 평가.

## 남은 검증 범위

- 이번 재검토에서는 카메라를 켜거나 실제 브라우저의 화면 조작을 반복하지 않았다. 기존 장비 검사와 미수행 항목은 [초기 학습 검증 보고서](custom-object-training-validation.md)를 참고한다.
- 실물의 양성 탐지 → 실제 사진 수집 → 원본/박스 육안 일치와 사용자 물체 정확도는 여전히 별도 확인이 필요하다.
- 30분 연속 실행, 장시간 학습, 실제 디스크 완전 소진·전원 중단·메모리 부족은 이번에 유발하지 않았다. 저장소 실패와 프로세스 정리 경로는 오류 주입으로 검사했다.
- 큰 데이터셋의 분할 탐색은 유한 횟수 휴리스틱이다. 모든 유효 분할을 찾는 보장은 없으며, 환경·근접 중복 분리와 클래스 양쪽 포함 조건을 완화해 통과시키지 않는다.
