# YOLOv8 실시간 탐지 UI 제안

작성일: 2026-11-06

**영상 중심의 다크 대시보드**를 권장합니다. 사용자가 먼저 “지금 무엇을 탐지하는가”, 다음으로 “정상적으로 처리하고 있는가”를 확인하도록 구성합니다. 현재 구현한 기본 화면은 http://127.0.0.1:8080 에서 확인할 수 있습니다. 네이티브 서버 직접 접속 주소는 http://127.0.0.1:8000 입니다.

## 1. 화면 구성

```text
┌──────────────────────────────────────────────────────────────────┐
│ LOCAL VISION LAB                                                  │
│ 실시간 객체 탐지 · YOLOv8                         ● 실시간 탐지 중 │
│ 카메라 영상을 이 Mac에서 분석합니다. 영상은 저장하지 않습니다.     │
├────────────────┬────────────────┬────────────────┬───────────────┤
│ 추론 백엔드    │ 탐지 속도      │ 서버 지연 p95  │ 현재 탐지 수  │
│ MPS / Core ML  │ — FPS          │ — ms           │ — 개          │
├──────────────────────────────────────────────┬───────────────────┤
│ 카메라                         1280 × 720     │ 탐지 결과         │
│                                              │                   │
│                                              │ 사람       96.2%  │
│           실시간 영상 + 탐지 박스            │ 의자       82.5%  │
│                                              │                   │
│                                              │ 최신 결과 기준    │
│ 최근 결과 시각 · 생략한 입력 수              │                   │
├──────────────────────────────────────────────┴───────────────────┤
│ ▸ 실행 설정                                                      │
│ 로컬 처리                                             API 문서 ↗ │
└──────────────────────────────────────────────────────────────────┘
```

위 객체와 confidence 값은 배치 설명용 예시입니다. 실제 화면은 서버가 보낸 결과만 표시합니다.

| 영역 | 제안 | 목적 |
| --- | --- | --- |
| 헤더 | 서비스명과 텍스트가 있는 상태 배지 | 연결·카메라·추론 상태를 즉시 파악 |
| 성능 요약 | 백엔드, 탐지 FPS, 서버 지연 p95, 현재 객체 수 | 처리 성능과 탐지 결과를 한 번에 확인 |
| 영상 | 데스크톱 본문의 약 70~75%, 원본 비율 유지 | 탐지 박스와 실제 물체의 일치 여부 확인 |
| 객체 목록 | 약 25~30%, 클래스명과 confidence | 영상 속 작은 라벨을 보완 |
| 실행 설정 | 기본 접힘, 현재 적용값 표시 | 입력 크기와 임계값을 필요할 때 확인 |
| 하단 | 결과 시각, 생략 프레임 수, API 문서 | 최신성 확인과 개발용 진입점 제공 |

탐지 FPS와 미리보기 FPS를 구분합니다. 서버 지연은 캡처한 프레임을 수신한 시점부터 결과 게시까지이며, 브라우저 전체 표시 지연으로 표현하지 않습니다. 목록은 최신 결과, 영상은 최대 15 FPS이므로 두 표시의 갱신 시점에는 차이가 있을 수 있습니다. 영상의 박스는 반드시 해당 영상 프레임의 결과를 사용합니다.

## 2. 시각 스타일

- 배경: 짙은 남색 `#0B1018`, 패널: `#131C29`, 경계선: `#233044`.
- 정상 상태와 주요 수치: 민트 `#68E4BD`. 대기·재연결: 황색. 오류: 적색.
- 상태는 색과 문구를 함께 사용하고, 애니메이션은 최소화합니다.
- 시스템 한글 글꼴을 사용하고 본문은 14px 이상, 주요 수치는 28~32px로 표시합니다.
- 탐지 confidence는 백분율로 표시합니다. 박스 좌표는 일반 보기에서 숨기고 추후 상세 정보로 분리하는 것을 권장합니다.
- 클래스의 한국어 이름을 추가한다면 `사람 · person`처럼 원래 모델 클래스명도 확인할 수 있게 합니다. 현재 구현은 모델 클래스명 원문을 표시합니다.

## 3. 상태별 동작

| 상태 | 화면 문구와 동작 |
| --- | --- |
| 모델 준비 | “모델을 준비하고 있습니다”와 영상 자리 표시자. 미확정 수치는 `—` |
| 정상 탐지 | 영상·박스·목록 갱신, “실시간 탐지 중” 배지 |
| 객체 없음 | 객체 수 `0`, “감지된 객체가 없습니다.” 이전 목록 즉시 제거 |
| 결과가 1초 이상 오래됨 | “영상 수신 지연”, 오래된 영상과 목록 숨김 |
| 카메라 오류 | “카메라 연결 대기”, 오류 원인과 재연결 상태 표시 |
| 서버 연결 끊김 | “서버 연결 끊김”, 자동 재연결, 마지막 영상을 실시간으로 표시하지 않음 |
| 모델 오류 | “실행 오류”, 원인을 표시하고 백엔드 자동 전환은 하지 않음 |

목록은 confidence가 높은 순서로 정렬하는 것을 권장합니다. 빠르게 바뀌는 목록 전체를 스크린리더의 실시간 알림으로 읽지 않고, 연결 상태 변경만 알립니다. 키보드로 설정 펼치기와 링크에 접근할 수 있어야 합니다.

## 4. 반응형 배치

- **넓은 화면(1000px 초과):** 영상과 객체 목록을 좌우 배치합니다.
- **태블릿·좁은 창:** 영상 아래에 객체 목록을 배치합니다.
- **모바일(650px 이하):** 성능 카드를 2×2로 배치하고 헤더 상태를 다음 줄로 이동합니다.
- 객체가 많아져도 영상 영역이 밀리지 않도록 목록만 스크롤합니다.

## 5. 현재 구현과 다음 개선안

현재 구현에는 다크 테마, 성능 카드, 실제 카메라 영상과 서버 렌더링 박스, 객체 목록, 상태 표시, 자동 재연결, 접을 수 있는 읽기 전용 실행 설정이 포함되어 있습니다. 실제 카메라와 Docker 중계 경로에서 화면 표시를 확인했습니다.

우선 추가할 조작은 다음과 같습니다. 아래 항목은 **제안이며 아직 구현되지 않았습니다.**

1. **영상 전체 화면:** 작은 객체의 박스와 라벨을 자세히 확인합니다.
2. **미리보기 일시정지 / 재개:** 브라우저 영상 구독만 중지합니다. 서버 추론은 계속되므로 “미리보기 일시정지 · 탐지는 계속 실행 중”을 표시합니다.
3. **객체 상세 펼치기:** 기본 목록에는 이름과 confidence를 표시하고, 좌표·클래스 ID는 펼쳤을 때 표시합니다.
4. **표시 클래스 필터:** 브라우저 목록의 필터임을 명시합니다. 박스나 서버 추론을 필터링하려면 별도 동작 설계가 필요합니다.

현재 서버는 실행 중 설정 변경 API가 없으므로, 백엔드 전환 버튼이나 confidence 슬라이더를 동작하는 제어처럼 표시하지 않습니다. 설정은 현재 값을 보여주고 “변경은 환경 변수 설정 후 서버 재시작으로 적용”이라고 안내합니다.

구현 파일: `app/static/index.html`, `app/static/style.css`, `app/static/app.js`.
