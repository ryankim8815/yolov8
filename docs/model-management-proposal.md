# 모델 관리 화면 제안

[브라우저에서 열어보는 시안](model-management-mockup/index.html) · [전체 화면 이미지](model-management-mockup/preview.jpg)

기존 **모델 버전** 메뉴를 **모델 관리**로 확장한다. 사용자가 목록에서 v2를 선택하면 v2가 무엇을 인식하는지, 어떤 가중치로 학습했는지 확인할 수 있다. 이때 실시간 탐지는 기존 v1으로 계속된다. **MPS에 적용**을 선택해야 서버의 실행 모델이 바뀐다.

시안은 카메라와 서버 없이 열린다. 사용자 모델, 생성일, 학습량, 평가 수치는 설명을 위한 예시다. 이름 변경과 모델 적용을 시험해도 새로고침하면 초기화된다.

| 사용자가 확인하려는 것 | 화면과 동작 |
| --- | --- |
| 이 모델을 알아보기 쉽게 부르고 싶다 | **이름 변경**에서 이 버전의 표시 이름만 수정한다. 같은 계열의 다른 버전과 학습 클래스 이름은 그대로다. 저장·취소를 제공하며 공백만 입력하면 저장할 수 없다. |
| 어디까지가 같은 모델인가? | **버전**과 **생성일(KST)**을 함께 표시한다. v1에서 이어 학습한 결과가 v2다. 같은 가중치를 변환한 PT와 Core ML은 한 버전 아래의 실행 형식이다. |
| 무엇을 인식하는가? | 선택한 가중치의 클래스마다 **학습 ID와 이름**을 함께 표시한다. 사용자 클래스와 COCO 80개를 합치지 않는다. 클래스가 10개 이상이면 이름과 숫자 ID로 검색한다. |
| 무엇으로 학습을 시작했는가? | **기반 모델(초기 가중치)**과 **아키텍처**를 분리한다. 예를 들어 v2의 기반 모델을 눌러 v1을 열고, 다시 YOLOv8n COCO까지 돌아갈 수 있다. |
| 이 버전을 실제로 쓸 수 있는가? | 같은 버전의 MPS·Core ML 사용 가능 여부, 검증 정확도(mAP50–95), 추론 지연(p95)을 보여준다. 실패와 미측정을 구분한다. **학습 이력 및 파일 정보**를 펼치면 데이터셋, 학습 작업, 입력 크기·batch·epochs, 모델 ID와 가중치 해시를 확인한다. |

## 기존 서버에 연결하는 방법

1. **조회와 이름 변경.** 기존 `GET /api/models`의 `active_model_id`, `backend`, `models`를 사용한다. 새 `PATCH /api/models/{id}`는 `{"name":"작업대 검사"}`만 받는다. 앞뒤 공백 제거 후 1~80자로 검증하고 SQLite에 표시 이름을 저장한다. 기본 모델과 경로 지정 모델은 서버 시작 때 다시 등록되므로 별칭을 ID별로 별도 보관하고 조회 시 합친다. 이름이 바뀌어도 모델 ID·파일 경로·해시·부모 참조·탐지 세션은 유지한다. 변경을 연결된 화면에도 알린다.
2. **버전과 날짜.** 현재 사용자 모델에 있는 고유 ID는 그대로 둔다. 제안하는 `family_id`와 `version_number`는 표시 이름과 독립적이다. 기본 가중치에서 시작하면 새 계열의 v1, 사용자 모델에서 이어 학습하면 같은 계열의 다음 번호를 등록 시 부여한다. 기존 레코드의 계보가 불명확하면 짧은 ID와 ‘버전 미기록’을 표시한다. 사용자 모델의 `created_at`은 KST로 표시하고 기본 모델의 생성일은 ‘미기록’으로 둔다. 외부 가중치의 등록 시각을 원본 생성일로 표시하지 않는다.
3. **클래스와 기반 모델.** 사용자 모델은 해당 버전의 `classes` 스냅샷을 사용한다. 현재 기본 모델 등록 정보의 클래스 배열은 비어 있으므로, 구현 시 기본 가중치의 라벨 매핑을 등록한다. 외부 모델은 자체 메타데이터가 없으면 ‘클래스 미확인’으로 표시한다. 기반 모델은 `initial_model_id`로 연결하고, 기본 가중치로 시작한 것이 확인된 경우에만 YOLOv8n COCO라고 표시한다. 보관된 `initial_sha256`으로 당시 가중치도 식별할 수 있다.
4. **비교와 적용.** `formats`에서 형식별 상태·평가 지표·해시를 읽고, 데이터셋·학습 정보는 `dataset_id`와 `job_id`로 연결한다. mAP는 평가한 데이터셋과 함께 표시하며 서로 다른 검증 세트의 수치를 순위로 비교하지 않는다. p95는 브라우저 표시 지연과 구분한다. 실제 적용은 현재 백엔드에서 준비된 형식에 한해 기존 `POST /api/models/{id}/activate`를 사용한다. 전환이 끝난 뒤 서버가 반환한 활성 모델로 표시를 갱신한다.

## 시안에서 확인할 순서

1. 처음에는 **v1 적용 중**, **v2 선택** 상태다. v2의 **이름 변경**으로 저장한 뒤 왼쪽 목록과 상세 제목만 갱신되는지 확인한다.
2. **기반 모델**을 눌러 v1의 Core ML 검증 실패 상태를 확인한다. 기본 모델까지 이동한 뒤 클래스 검색에 `41`을 입력하면 `cup`이 나온다.
3. 다른 버전에서 **MPS에 적용**을 누르고 취소하면 현재 모델이 유지된다. 확인하면 시안 안의 적용 표시가 이동한다. 실제 서비스 변경, 삭제, 파일 이동은 수행하지 않는다.
