이 문서는 초기 구현 검증 기록이다. 이후 오류 재현·수정과 환경별 **68개 Python / 5개 JavaScript 테스트**, 추가 실장비 smoke 결과는 [구현 후 검토 보고서](post-implementation-review.md)에 기록했다.

## 결과 요약

수집·검토·고정 데이터셋·학습·평가·Core ML·모델 버전 선택 코드를 구현했다. 자동 테스트 **55개가 MPS, Core ML, train 환경에서 각각 모두 통과**했다. 실제 MPS 1 epoch 학습과 Core ML 변환을 두 차례 실행했고, 최종 실행은 한글 클래스와 고정 이미지 목록으로 완료했다. 실제 카메라 미검출 대기·저장 중지·명시적 카메라 해제 및 생성 모델의 브라우저 적용·원본 복귀를 확인했다.

**실물 대상이 중앙에서 탐지되는 상황의 실제 사진 수집·박스 일치와 사용자 물체 정확도는 아직 실장비 검증하지 못했다.** 카메라는 정상 동작했으나 관측 장면에서 탐지된 대상이 없었다. 원본/박스 일치와 양성 수집은 하드웨어 대체 입력의 자동 검사로 확인했다.

## 실제 MPS 학습·Core ML 변환

명령: `bash scripts/python.sh train -m scripts.smoke_training`

공개 COCO128에서 단일 객체 라벨을 가진 이미지 10장을 별도 테스트 저장소로 복제하고, 기능 검사 목적으로 하나의 `검증_물체` 클래스로 재라벨링했다. 환경·중복 분할로 train 8장, validation 2장을 고정했다. 실제 사용자 사진이나 실제 서비스 DB를 사용하지 않았다.

최종 작업: `job-4abc2580f4d64eaba7eddb1d324e15eb`

- 상태: `completed`, MPS 학습 → PT 평가 → FP16 Core ML 변환 → 동일 검증 자료 평가.
- 설정: MPS, 640, batch 4, 1 epoch, patience 1, workers 0, cache False, AMP False, AdamW, seed 42.
- 클래스 이름 `검증_물체`가 PT와 Core ML에서 동일하게 복원됨.
- 클래스 매핑·출력 차원·워밍업·원본 좌표의 유한성 검증 통과.
- Core ML runtime: `ComputeUnit.CPU_AND_NE`, raw `[1, 5, 8400]` 계열 출력, 공통 NMS.
- 신규 버전 자동 활성화 없음. smoke 저장소에만 등록.

## 실제 카메라·브라우저

실제 Core ML 서버는 `YOLO_STATE_DIR=.../artifacts/camera-training-check`로 실행했다. 브라우저에서 클래스·환경 등록과 수집 시작을 조작했다.

- 내장 카메라의 실제 입력 1280×720 확인.
- 한 시점 상태 표본: 탐지 29.1 FPS, JPEG 12.5 FPS, 서버 지연 p95 28.388ms. 장시간 안정성 측정은 아니다.
- 미검출 대기에서 1,501개 처리 프레임을 생략하고 저장 0장 유지.
- `사진 저장 중지` 완료 후 카메라 미리보기 유지.
- 실제 생성한 1클래스 Core ML 모델 적용 완료 후 COCO80 모델로 복귀 완료. 전환 중 상태·버전 변경 표시 확인.
- `카메라 끄기` 후 준비 비활성화·영상 제거·명시적 꺼짐 확인.
- 통합 종료 명령으로 검증 서버 정상 종료. 확인 후 실제 카메라를 실행 중으로 남기지 않음.

추가 브라우저 검사는 카메라를 대체한 `:8001` 테스트 서버에서 수행했다. 썸네일/자동 박스 표시 → 선택 제외 → 선택 승인 → 고정 데이터셋 생성 → 학습 화면 데이터셋 표시 흐름을 확인했다. 이 경우의 결과는 실제 카메라 양성 수집 검증으로 계산하지 않는다. 브라우저 콘솔 JS 오류는 없었다. 테스트 서버도 종료했다.

## 남은 실사용 확인

- 실제 물체를 중앙에 놓고 양성 탐지 → 사진 저장 → 원본 이미지와 박스 일치를 육안 확인.
- 해당 물체의 여러 배경·조명·각도 자료를 충분히 모아 실제 accuracy 평가. 유사한 다른 물체와 혼동 여부도 포함.
- 실물 사용자 데이터로 충분히 학습한 PT와 Core ML의 변환 품질 확인. 이번 0 mAP smoke 결과로 대체하지 않음.
- 실제 메모리 부족 상황, 전원 중단, 장시간 학습의 내구성은 강제로 유발하지 않았다. 관련 오류·중지 guard는 자동 검사로 확인했다.
- dHash는 보조 휴리스틱이다. 모든 근접 중복을 보장하지 않으므로 환경 그룹 지정과 검토가 필요하다.
